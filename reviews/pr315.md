## Additional findings

1. **PGP public key MPI leak** (grub-core/commands/pgp.c:361): When MPI parsing fails mid-loop,
the error path now frees all successfully allocated mpis before freeing sk. The check
`if (sk->mpis[j])` skips unallocated entries (sk is grub_zalloc'd, so NULLs are safe).

2. **PGP signature verification leak** (pgp.c:531): Initializes mpis[10], hsexp, pubkey, and
sig to NULL, then adds cleanup code on both success and failure paths. Before the patch, the
success path leaked all four resources; now both paths call _gcry_mpi_release and
_gcry_sexp_release.

3. **X.509 KeyUsage buffer overflow** (grub-core/commands/appendedsig/x509.c:227): Fixes
`usage_size = sizeof (usage_size)` → `sizeof (usage)`. The variable usage is grub_uint8_t (1
byte), but usage_size was initialized to sizeof(grub_int32_t) = 4, telling asn1_read_value
a 1-byte buffer has 4 bytes of room, risking a 3-byte stack overwrite.

4. **X.509 serial number leak** (x509.c:903): When x509_get_validity() fails, the error path
now jumps to cleanup_serial instead of exit, ensuring cert->serial (allocated earlier by
x509_get_serial) is freed. The cleanup labels follow LIFO order: cleanup_pk → cleanup_exit →
cleanup_serial → exit.

5. **X.509 certificate comparison** (x509.c:1007, 1022): Allows NULL subject/issuer by
checking `(cert1->subject == NULL) != (cert2->subject == NULL)` (XOR logic) instead of
rejecting any NULL. Two missing names are now equal, and grub_memcmp is guarded with
`if (cert1->subject != NULL && ...)` to prevent dereferencing NULL. This allows certificates
without commonName (permitted by RFC 5280) to match themselves, fixing dbx revocation.

6. **ASN.1 name size initialization** (grub-core/commands/appendedsig/asn1_util.c:222): Sets
`*name_size = 0` when no OID match is found, ensuring consistent state when
grub_asn1_read_rnd_sequence() leaves *name NULL.
