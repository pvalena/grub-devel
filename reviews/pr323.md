# AI Review: MR !323 - Defer configfile screen clear until visible output

4 commits that stop `configfile` from clearing the screen up front, so an untouched EFI console (firmware splash)
survives a silent or hidden-menu autoboot configfile. Commit 1 does this with a `grub_xputs` hook; commit 2 replaces
it with a per-terminal pending-clear flag (new `prepare` callback) plus a functional test; commits 3-4 extend and trim
that test.

**Commits:**
1. **dbd414894** - configfile: Defer screen clear until visible output
2. **e43b88694** - term: Defer configfile clear per output terminal
3. **06e3faabf** - tests: Exercise configfile deferred clear
4. **a8b293219** - tests: Consolidate configfile terminal coverage

## Issues Found

No issues found.

## Additional findings

Only the EFI console implements `prepare`; other terminals keep the immediate clear. The EFI hooks sit on the one
path that switches the console to text mode, so ACTIVE/PENDING stay in step with `text_mode` (`prepare`/`fini`).
The `sleep --verbose` prepare call does perform the pending clear on EFI, but has no visible effect there: `getxy`
reports 0,0 until prepared, so the saved cursor position is the same either way (it matters for the test's fakes).
A pending clear wins over the `debug` newline rule on an untouched console (observation, not a defect).
Commit 1's hook and generation counter are removed by commit 2, so the series reads better squashed. Not built or run.
