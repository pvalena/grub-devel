# AI Review: MR !273 - Ignore ea_inode INCOMPAT feature

1 commit adds `EXT4_FEATURE_INCOMPAT_EA_INODE` (0x0400) to `EXT2_DRIVER_IGNORED_INCOMPAT` so
GRUB's read-only ext2/3/4 driver no longer refuses to mount filesystems with large
extended-attribute values stored in dedicated `ea_inode`s (needed for CNSA 2.0 / ML-DSA-87
sized IMA xattrs).

## Additional findings

`0x0400` does not collide with any other flag in the `EXT2_FEATURE_INCOMPAT_*`/
`EXT4_FEATURE_INCOMPAT_*` list (0x0001..0x0200, 0x2000, 0x4000, 0x10000 are the others already
defined in this file) and matches the upstream e2fsprogs/Linux kernel value for
`EXT4_FEATURE_INCOMPAT_EA_INODE`.

The commit's core claim -- "GRUB never reads extended attributes" -- holds: `grub-core/fs/ext2.c`
has no xattr/`i_file_acl`/`ea_inode` parsing code at all, so a feature bit that only changes
*where* large xattr values are stored cannot affect this driver's behavior. The bit is added to
`EXT2_DRIVER_IGNORED_INCOMPAT` (not `EXT2_DRIVER_SUPPORTED_INCOMPAT`), consistent with the other
entries in that ignore-list, and the mount-time check at ext2.c:706-708 masks against
`~(EXT2_DRIVER_SUPPORTED_INCOMPAT | EXT2_DRIVER_IGNORED_INCOMPAT)`, so this bit correctly stops
being treated as an unsupported/rejecting feature.
