## Additional findings

The new `grub_le_to_cpu32 (diro->inode.size) > GRUB_EXT2_SYMLINK_MAXLEN` check sits after the
inode is read and before the `grub_add (size, 1, &sz)` overflow check and `grub_malloc (sz)`,
so it caps the allocation for a hostile `inode.size` (previously only `grub_add` overflow was
caught, so a value like `0xFFFFFFFE` still attempted a ~4 GiB allocation). The fast-symlink
path (`inode.size < sizeof (inode.symlink)` = 60, copied inline) and the terminating
`symlink[inode.size] = '\0'` write stay in bounds under the new limit (buffer is `size + 1`).
`4096` allows a full PATH_MAX target; `> 4096` rejects larger. Consistent with the sibling
error returns in the function.
