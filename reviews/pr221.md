# AI Review: MR !221 - ieee1275: Call IBM CAS when last booted OS was AIX

1 commit in `grub_claim_heap()` (`grub-core/kern/ieee1275/init.c`, powerpc only): reads `/options` `real-base` and, when
it equals the AIX default (0x2800000) and the RMO is at most 512 MB, also triggers `grub_ieee1275_ibm_cas()`.

**Commits:**
1. **ed5e41cc8** - ieee1275: Call IBM CAS when last booted OS was AIX

## Issues Found

### Issue 1: Non-numeric `real-base` text leaves a stale `grub_errno`, so the console is never registered with terminfo

**Location:** `grub-core/kern/ieee1275/init.c`, `grub_claim_heap()`, line 961

`real_base = grub_strtoul (real_base_str, 0, 10);` raises `GRUB_ERR_BAD_NUMBER` (`kern/misc.c:650-653`) whenever the
text does not start with a decimal digit, and nothing clears it. `grub_machine_init()` calls `grub_claim_heap ()` and
then `grub_console_init_lately ()` (`init.c:1100-1101`), which calls `grub_terminfo_output_register ()`
(`term/ieee1275/console.c:256`). Its `grub_terminfo_set_current ()` call fills in the terminfo strings but ends the
ieee1275 branch with `return grub_errno;` (`term/terminfo.c:168`), so it returns the stale error although every
`grub_strdup` succeeded. `grub_terminfo_output_register ()` then returns early (`terminfo.c:197`) and never links the
console into `terminfo_outputs` (`terminfo.c:201-202`). The return value is ignored by the caller. Effects: the
`terminfo` command neither lists `console` nor can configure it (`terminal console isn't found or it's not handled by
terminfo`, `terminfo.c:778-779`), and `grub_load_modules()` later prints "error: unrecognized number." (`main.c:72-73`).
`kern/ieee1275/openfw.c:533-534` clears `grub_errno` after a non-fatal `grub_strtoul`; the new code does not.

Conditional trigger: the code runs only when `GRUB_IEEE1275_FLAG_CAN_TRY_CAS_FOR_MORE_MEMORY` is set (powerpc,
`compatible` starting with "IBM,", `cmain.c:128-130`) and `/options` has a `real-base` whose text lacks a leading
decimal digit, e.g. `"c00000"`, `""` or `"-1"`. The firmware's text format for `real-base` is not in the tree and was
not checked. The constant is `0x2800000` but the parse is base 10: if the firmware writes hex-style text, an AIX value
`"2800000"` never matches, and a non-AIX value such as `"c00000"` would hit this error path.

**Draft fix** -- clear the error raised by the best-effort parse:

```diff
--- a/grub-core/kern/ieee1275/init.c
+++ b/grub-core/kern/ieee1275/init.c
@@ grub_claim_heap (void)
               real_base_str[sizeof (real_base_str) - 1] = 0;
               real_base = grub_strtoul (real_base_str, 0, 10);
+              grub_errno = GRUB_ERR_NONE;
               if (real_base == AIX_DEFAULT_REAL_BASE
```

If `err != GRUB_ERR_NONE` (memory sizing failed) this clear would also drop that earlier error; wrapping the
detection in `if (err == GRUB_ERR_NONE)` avoids it, since `aix_boot_detected` is only used when
`err == GRUB_ERR_NONE`.

## Additional findings

The new trigger only adds the `rmo_top == 512 MB` case; the old `rmo_top < 512 MB` path and the unchanged
`!ibm_ca_support_reboot` / `err == GRUB_ERR_NONE` guards still apply, so a CAS reboot cannot re-trigger CAS.
`real-base` is parsed with base-10 `grub_strtoul()` as `term/ieee1275/console.c` does for `screen-#columns`; if the
firmware reports hex text, the AIX case would never match. Not tested on firmware.
