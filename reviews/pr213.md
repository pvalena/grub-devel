## Additional findings

The `direl + 1` to `cdirel + 1` fix in all three DIR_ITEM loops
(`find_path`, `grub_btrfs_dir`, `grub_btrfs_get_default_subvolume_id`)
is the same one-token change. With the old `direl + 1`, the loop
recomputed each offset from the first entry rather than accumulating,
so the third entry onward landed at the wrong position. With a
single packed entry (the common case) the bug was invisible.

The `sys_chunk_array_size` field is correctly placed in the
superblock struct: `dummy3a[0x10] + uint32 + dummy3b[0x25] = 0x39`,
matching the original `dummy3[0x39]`. The behavior change from
`break` to `return grub_error()` on a non-chunk key type within the
valid region is intentional: stale keys past the valid size were the
root cause, and a non-chunk key within the valid range indicates
corruption.
