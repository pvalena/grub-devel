# AI Review: MR !285 - grub-core/lib/arg: Fix memory leak on argument-parse failure

1 commit fixes a memory leak in `grub_arg_parse()`: the dynamically-grown `argl` array of
non-option arguments was never freed on the `fail:` error path.

**Commits:**
1. **576d9f967** - grub-core/lib/arg: fix memory leak when argument parsing fails

## Issues Found

No issues found.

## Additional findings

`argl` only ever stores pointers borrowed from `argv` (`add_arg()` is always called with an
`argv[...]` element, never a separately-allocated string), so `grub_free (argl)` on the new
`fail:` path frees only the array itself and cannot double-free or free caller-owned storage.
The sole caller, `grub_extcmd_dispatcher()` (`grub-core/commands/extcmd.c`), declares `new_args`
uninitialized and never reads it unless `grub_arg_parse()` returns success (`*args` is only
written on the success path at the end of the function), so the caller genuinely has no way to
reach or free `argl` itself, matching the commit message's description of the bug. Inside
`add_arg()`, the one pre-existing internal failure path (`grub_realloc` returning NULL) already
sets `*argl` to NULL before returning, so the new `grub_free (argl)` in the caller's `fail:`
label is a safe no-op (`grub_free(NULL)`) in that case rather than a double-free.
