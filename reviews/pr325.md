## Issues Found

### Issue 1: `grub-core/osdep/basic/platform.c` includes libc headers before `config.h`, which the new gnulib rejects

**Location:** `grub-core/osdep/basic/platform.c`, line 19 (first include); reached via `grub-core/osdep/platform.c`

On any host that is not Linux, MinGW or Cygwin, `osdep/platform.c` (no includes of its own) falls through to
`#include "basic/platform.c"`, whose first include is `<grub/util/install.h>`. That header starts with
`<sys/types.h>` and `<stdio.h>` (install.h:22-23), before any `config.h`. The programs that compile it
(grub-mkrescue, grub-mkstandalone, grub-install, grub-mknetdir, `Makefile.util.def:618,662,707,746`) get
`CPPFLAGS_GNULIB` (`Makefile.am:22`, `Makefile.util.def:6`), so those two headers resolve to gnulib's replacement
headers. At the pinned gnulib, `lib/sys_types.in.h:26-28` and `lib/stdio.in.h:64-66` both contain
`#if !_GL_CONFIG_H_INCLUDED` / `#error "Please include config.h first."`; the previous gnulib (`9f48fb99`) has neither.
Nothing includes `config.h` earlier (no `-include` in the build flags; `osdep/platform.c` has no includes). The
translation unit therefore stops with that `#error` after this MR, where it built before. Every sibling already
includes a config header first (`linux/platform.c`, `unix/platform.c` use `<config.h>`), and commit 1 of this MR fixes
the same failure for `tests/` and `osdep/unix/sleep.c`, which shows the wrappers are active in these builds. This file
was missed because Linux CI never takes the `basic/platform.c` branch.

**Draft fix** -- include `config.h` first, as the siblings do (fold into commit 1):

```diff
--- a/grub-core/osdep/basic/platform.c
+++ b/grub-core/osdep/basic/platform.c
@@ -16,4 +16,5 @@
  *  along with GRUB.  If not, see <http://www.gnu.org/licenses/>.
  */
 
+#include <config.h>
 #include <grub/util/install.h>
```

Not built on a non-Linux host: the `#error` text and conditions were read from gnulib source, the include chain from
this tree.
