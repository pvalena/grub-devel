# AI Review: MR !284 - util/grub-mkimagexx: Fix memory leak in raw relocation list

1 commit fixes a memory leak in `grub-mkimage`'s raw-relocation translation path: the
per-image linked list of `struct raw_reloc` nodes was built up and converted into the final
on-disk relocation section, but the list nodes themselves were never freed.

**Commits:**
1. **324e1647e** - util/grub-mkimagexx: fix memory leak when processing raw relocation entries

## Issues Found

No issues found.

## Additional findings

`struct raw_reloc` nodes are plain `xmalloc`'d list nodes (no embedded array member), each
allocated individually in `translate_relocation_raw()`, so the new free loop in
`finish_reloc_translation_raw()` is a straightforward one-free-per-node cleanup with no
double-free risk. The `struct translate_context ctx` that owns the list is a stack local
declared fresh in `make_reloc_section()` for every image built, used once (start, accumulate,
finish) and discarded, so the fix needs no explicit NULL-reset of `ctx->raw_relocs` afterward.
The early-return branch for an empty list (`if (!ctx->raw_relocs) { ...; return; }`) is
untouched and correctly has nothing to free.
