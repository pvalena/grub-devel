## Additional findings

The tar memory leak fix restructures `grub_cpio_find_file()` to
route all error and end-of-archive exits through a single `fail:`
label that frees `*name` and sets it to `NULL`, preventing the
caller from seeing a stale pointer. The oversized-alloc bound uses
`grub_disk_native_sectors()` -- since the name/link is stored in
the archive, it cannot exceed the device size. The SquashFS
`memcpy` OOB fix correctly accounts for the trailing `stack[1]`
already included in `sizeof(*dir)`: the copy size is now
`sizeof(*dir) + (stsize - 1) * sizeof(stack[0])` instead of the
previous `sizeof(*dir) + stsize * sizeof(stack[0])`.

[pr210_investigation.txt](https://github.com/pvalena/grub-devel/blob/main/reviews/pr210_investigation.txt).
