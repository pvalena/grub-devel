## Additional findings

The fix copies each namespace entry into a local `namespaces_table[TABLE_SIZE]` array *before*
calling `grub_ieee1275_close (ihandle)`, matching the pattern this same function already uses,
and documents, for the two other firmware buffers it reads (`discovery_controllers_table` and
`nvme_controllers_table`): "After closing the device, the info is lost. So lets copy each buffer
in the buffers table." The removed unconditional `dev_iterate_real (buf, buf)` after the
namespace loop was a genuine duplicate registration (it re-registered whatever path `buf` last
held -- either the last namespace, or, with zero namespaces, the bare controller path with no
namespace suffix).

The new `if (num_namespaces > TABLE_SIZE) num_namespaces = TABLE_SIZE;` clamp is a real
improvement this MR adds beyond its stated scope: it guards the new local-array copy loop against
overflowing `namespaces_table[256]` if firmware reports more than 256 namespaces. The two sibling
copy loops in the same function (`discovery_controllers_table.table[TABLE_SIZE]` and
`nvme_controllers_table[TABLE_SIZE]`) still copy `nentries` firmware-reported entries into their
fixed 256-entry arrays with no equivalent clamp -- pre-existing, untouched by this diff, so out of
scope here, but the same latent overflow risk this MR just fixed for namespaces.
