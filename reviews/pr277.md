# AI Review: MR !277 - fs/zfs/zfs: Allow pools with OpenZFS native encryption and large dnodes

2 commits that let the ZFS driver open pools with the `com.datto:encryption` and `org.zfsonlinux:large_dnode`
features active, and refuse (with an error) any read that would need an encryption key or a large dnode.

**Commits:**
1. **ce6ebd0de** - fs/zfs/zfs: Allow pools with OpenZFS native encryption
2. **cfd8376c8** - fs/zfs/zfs: Allow pools with large dnodes

## Issues Found

No issues found.

## Additional findings

Both commits are Claude-assisted (Co-Authored-By trailer); the commit messages match the code. Not built or run.
Encryption: on pool version 5000 only a level-0 objset block with bit 61 is read (plain); every other bit-61 block
returns an error, and older pools keep the Oracle bits 60-61 path. Large dnodes: `dnode_get()` is the only reader of
dnode blocks and now rejects `dn_extra_slots != 0`; `check_dataset_readable()` only skips the root-dir mtime.
Two premises come from the author's description, not from a source I read: the MOS never holds large dnodes, and an
encrypted dataset's objset block keeps a full checksum in `blk_cksum`.
