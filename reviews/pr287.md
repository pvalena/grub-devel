# AI Review: MR !287 - util/grub-mkimagexx: Preserve negative RISC-V PC-relative offsets

1 commit fixes an ELF32 host-tool bug in RISC-V relocation processing: when resolving an
`R_RISCV_PCREL_LO12_I`/`R_RISCV_PCREL_LO12_S` relocation, `grub-mkimage` searches backward for
the matching `R_RISCV_PCREL_HI20` relocation and recomputes the symbol-to-PC distance from that
earlier instruction's own symbol and addend. On ELF32 that distance was computed in unsigned
32-bit `Elf_Addr` arithmetic before being assigned to the signed `grub_int64_t` accumulator, so a
backward reference (HI20 target located after the LO12 site) wrapped to a huge unsigned value
instead of staying negative, corrupting the encoded immediate.

## Additional findings

The fix adds `Elf_Sxword` (`Elf32_Sword` / `Elf64_Sxword`, `util/grub-mkimage32.c` and
`util/grub-mkimage64.c`) as the type for `rel2_addend`, matching the ELF spec's own (signed)
type for `Elf32_Rela.r_addend` / `Elf64_Rela.r_addend` (`include/grub/elf.h:507,514`) rather than
reusing the unsigned `Elf_Addr`. `rel2_off` is then computed as
`(grub_int64_t) rel2_sym_addr + rel2_addend - (grub_int64_t) rel2_loc`, all in 64-bit signed
arithmetic, so a negative distance is preserved instead of wrapping. Traced the sign handling
through `grub_target_to_host()` (`include/grub/util/mkimage.h`), which round-trips the addend
through a `grub_uint64_t` parameter and (for ELF32) an inner `grub_uint32_t` parameter before
returning; a concrete example (addend -100) confirms the original 32-bit two's-complement bit
pattern survives that round trip intact regardless of the intermediate widening being sign- or
zero-extending, so casting the final `grub_uint64_t` result back to `Elf_Sxword` correctly
recovers -100 on both ELF32 and ELF64. The forward-reference (non-negative distance) case is
unchanged in outcome, since unsigned and signed 64-bit arithmetic agree whenever the true
difference is non-negative. For more details, see
[pr287_investigation.txt](https://gitlab.freedesktop.org/pvalena/grub/-/blob/main/reviews/pr287_investigation.txt).
