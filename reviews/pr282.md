# AI Review: MR !282 - Fix memory leak in finish_reloc_translation_raw()

1 commit adds the missing deallocation of the `ctx->raw_relocs` linked list built up during raw
(non-PE) relocation translation in `grub-mkimage`.

**Commits:**

## Additional findings

`translate_relocation_raw()` prepends one heap-allocated `struct raw_reloc` per relocation onto
`ctx->raw_relocs`. `finish_reloc_translation_raw()` previously walked that list once to size and
fill `layout->reloc_section`, then returned without freeing any of the nodes; the empty-list early
return (`if (!ctx->raw_relocs)`) correctly needs no free since nothing was allocated in that case.
The added `while (ctx->raw_relocs) { next = ...; free (...); ctx->raw_relocs = next; }` loop runs
only after the list has already been fully read into `layout->reloc_section`, so there is no
use-after-free, and it walks every node exactly once, so no double-free. `ctx` is a stack-local
`struct translate_context` in `make_reloc_section()`, called once per `grub-mkimage` invocation, so
the leak was bounded (reclaimed at process exit) but genuine on every raw-target image build; the
fix is a plain, self-contained list teardown with no interaction with the PE (`finish_reloc_translation_pe`)
path, which already frees its own list correctly.
