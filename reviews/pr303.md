1 commit adds a CI job that validates commit message structure for MR pipelines: line 1 (subject)
must be non-empty, line 2 must be blank, and lines 3+ (body) must contain at least one non-empty
line. Enforces the conventional "subject, blank line, body" format via an AWK script
(`.gitlab-ci/script/metadata-format.sh`) that processes each commit in the MR.

## Additional findings

The AWK script correctly handles edge cases: a one-line message (no blank separator) fails at END
with "must contain at least 3 lines"; a two-line message (subject + blank, no body) fails the same
way; a message with subject + blank + all-whitespace body fails with "body must contain at least
one non-empty line" (body_count stays 0). The shell safety is correct (`set -eu -o pipefail`), and
the unquoted `$COMMITS` in the for-loop is intentional (word-splitting on whitespace to iterate
over SHAs). The CI YAML integration runs the job only on MR pipelines (`if: $CI_PIPELINE_SOURCE ==
"merge_request_event"`), preventing false failures on direct pushes to branches.
