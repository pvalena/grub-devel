== Verification of the applied fix ==

Read `util/grub-mkconfig.in` at pr297 (9e1b528f6), lines 315-322:

```sh
if [ -n "${GRUB_MODULE_STATE_FILE}" ]; then
  export GRUB_MODULE_STATE_FILE
  oldumask=$(umask); umask 077
  > "${GRUB_MODULE_STATE_FILE}"
  umask $oldumask
  trap 'test -n "${GRUB_MODULE_STATE_FILE}" && rm -f "${GRUB_MODULE_STATE_FILE}"' EXIT
  # Some shells (e.g. dash) skip the EXIT trap when killed by a signal.
  # Exit explicitly instead, so the EXIT trap runs and the script stops.
```

The file creation `> "${GRUB_MODULE_STATE_FILE}"` now runs under `umask 077`, creating it at mode
`0600` (user-only read/write) regardless of the ambient umask, matching the hardening already
applied to `${grub_cfg}.new` (lines 282-288) and the final `${grub_cfg}` copy (lines 303-310). The
umask restore immediately follows, limiting the hardened scope to just this file creation. This
removes the world-readable state-file gap from the prior version.

Cross-referenced with the prior review's sibling-function comparison: lines 282-288 and 303-310 use
the identical `oldumask=$(umask); umask 077` / `umask $oldumask` idiom, confirming consistency.

== Cross-commit interaction re-verification ==

The fix to commit 1 (umask hardening) does not affect the cross-commit interaction analyzed in the
prior review. That interaction is:

1. Commit 1 creates a shared state file (`${grub_cfg}.modules`) that `util/grub.d/*.in` scripts
   append to (via `grub_record_module`) and consult (via `grub_is_module_recorded`) during the
   loop through `/etc/grub.d/*` scripts (which runs in lexical order: 00_, 10_, 20_, ...).
2. Commit 2 (`00_header.in`, the first script in the loop) uses `grub_is_module_recorded` to skip
   re-preparing a device for font/theme/background when the required modules were already emitted
   at the top level of grub.cfg (recorded by commit 1's logic).

The state file's permission bits (the only thing the fix changed) have no bearing on this
interaction: the scripts still write to and read from the file in the same way, under the same trap
cleanup (EXIT + explicit-exit-on-signal), and the file is still removed after the grub.d loop
completes. The umask hardening only affects who else on the system can read the file while it
exists (now user-only, previously world-readable under a typical `022` umask).
