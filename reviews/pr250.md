## Additional findings

All five fixes address real bugs verified by reading source:

1. **hfs.c** (line 1317): `grub_hfs_find_dir()` can succeed without setting `found` (returns 0, leaves output
   param NULL), then line 1323 `grub_memcpy(..., found->fdrec.frec.extents, ...)` dereferences NULL. Fix
   adds NULL check before memcpy.

2. **diskfilter.c** (line 1097): `totsize = (nmemb - level/3) * disk_size` can overflow on large RAID arrays.
   Fix uses `grub_mul()` to detect overflow and fail gracefully instead of wrapping silently.

3. **ahci.c** (lines 376, 386, 466, 756): Four error paths leaked `adevs[i]` struct after DMA allocation
   failures. Fix adds `grub_free(adevs[i])` on all failure paths and adds missing NULL check for `rfis`
   allocation (line 463) - the old code would dereference NULL at line 468 if allocation failed.

4. **ata.c** (lines 470, 581): Two paths returned error on device-type mismatch without freeing the `ata`
   struct. Fix adds `grub_ata_real_close(ata)` before error return, and adds the missing `grub_free(ata)` to
   the close function itself (line 366) - confirmed the struct is allocated at line 429 but was never freed.

5. **usbms.c** (line 655): `GRUB_MOD_FINI` loops over `grub_usbms_devices[]` array dereferencing each entry
   without checking for NULL. Module detach can leave NULL entries. Fix adds NULL check before dereference.

All fixes match the resource-leak and null-deref patterns from `docs/BUG_PATTERNS.md`. Verified each by
reading the actual allocation/free/dereference sites in the source, not just the diffs.
