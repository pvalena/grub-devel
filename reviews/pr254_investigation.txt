MR !254 - In-place verification to reduce memory usage - 5 commits (AI-assisted)

This investigation documents the security verification of the in-place verification feature, which adds a
new code path for TPM/TPCM measurement. The feature is security-critical because it handles verification of
initrd files that the kernel will consume, and any weakness could allow unverified data to reach the kernel.

Source files read for verification:
- grub-core/kern/verifiers.c (pr254, origin/master)
- grub-core/kern/file.c (pr254, origin/master)
- grub-core/loader/linux.c (pr254, origin/master)
- grub-core/commands/tpm.c (pr254)
- grub-core/commands/tpcm.c (pr254)
- include/grub/file.h (pr254)
- include/grub/verify.h (pr254)

== 1. VERIFY_IN_PLACE + NO_DECOMPRESS coupling enforcement ==

Location: grub-core/kern/verifiers.c:123-128

The code enforces that VERIFY_IN_PLACE cannot be used without NO_DECOMPRESS:

  if (in_place && !(type & GRUB_FILE_TYPE_NO_DECOMPRESS))
    {
      grub_error (GRUB_ERR_BAD_ARGUMENT,
                  "GRUB_FILE_TYPE_VERIFY_IN_PLACE requires GRUB_FILE_TYPE_NO_DECOMPRESS");
      return NULL;
    }

This check happens at the very start of grub_verifiers_open() (after exemption check at line 132), before
any verifiers run. If the condition is violated, the function returns NULL immediately (line 127), causing
grub_file_open() to fail.

Why this coupling matters (verifiers.c:118-121):
The verify filter (GRUB_FILE_FILTER_VERIFY = 0) runs before compression filters in the filter chain. Without
NO_DECOMPRESS:
  - grub_verifiers_open() would hash compressed bytes at open time (if a non-in-place verifier ran)
  - grub_verify_in_place() would hash decompressed bytes from the loaded buffer
  - Result: hash mismatch even for legitimate files

Verified the flag is set correctly at the call site:
- loader/linux.c:230-231 opens initrd files with both flags:
    GRUB_FILE_TYPE_LINUX_INITRD | GRUB_FILE_TYPE_NO_DECOMPRESS | GRUB_FILE_TYPE_VERIFY_IN_PLACE

Bypass check:
Attempted to find any code path that could bypass the check. The check is in grub_verifiers_open(), which is
registered as GRUB_FILE_FILTER_VERIFY (verifiers.c:293). All grub_file_open() calls go through the filter
chain, so there is no way to open a file with VERIFY_IN_PLACE without this check running first. The only
files that skip verification entirely are those matching grub_verifiers_exempt() (lines 91-101: signature
files, memdisk, procfs) - these cannot trigger the in-place path because they return early at line 132.

== 2. Unverified data cannot reach the kernel ==

Location: grub-core/loader/linux.c:362-377 (fail path)

On any error during initrd load or verification, the entire target buffer is wiped:

  grub_memset (target, 0, initrd_ctx->size);

Traced all error paths in grub_initrd_load():
1. insert_dir failure (line 307): goto fail → wipes buffer (line 373)
2. grub_file_read failure (line 330): goto fail → wipes buffer (line 373)
3. grub_verify_in_place failure (line 347): goto fail → wipes buffer (line 373)

The wipe uses initrd_ctx->size, which is the full allocated size (computed in grub_initrd_init() at line
258-260 and verified at allocate_pages()). This ensures every byte that might have been written is zeroed,
not just the bytes from the failed component.

Cross-checked the target buffer:
- loader/i386/linux.c passes prot_mode_mem as target (would be line ~1052 in the modified version)
- This is the buffer the kernel will actually consume
- On EFI LoadFile2 path, target is owned by the Linux EFI stub
- Wiping prevents unverified data from remaining in memory that could be consumed later

verify_pending flag:
- Set by grub_verifiers_open() when in-place verifiers are deferred (verifiers.c:146, 258)
- Cleared by grub_verify_in_place() at line 326
- If file is closed without calling grub_verify_in_place(), file.c:207 logs a debug warning
- The flag cannot be left set after grub_initrd_load() because:
  * Success path: grub_verify_in_place() clears it (line 326)
  * Failure path: goto fail → grub_initrd_close() → grub_file_close() (line 375) clears it
  * Either way, the file is closed before returning

== 3. No TOCTOU between load and verify ==

Time-of-check-to-time-of-use analysis:

The sequence in grub_initrd_load() at loader/linux.c:323-347 is:
1. Line 326: cursize = grub_file_read (file, ptr, ...)
2. Line 342: grub_verify_in_place (file, ptr, cursize)
3. Line 349: ptr += cursize (advance to next component)

Between the load (line 326) and verify (line 342), no other code runs that could:
- Modify the buffer (ptr is the write target, not readable by other code)
- Access the data (kernel has not been started yet on the normal path)
- Change the file (file is read-only; grub_file_read() does not modify the underlying data)

On the EFI LoadFile2 path (mentioned in commit message as a special case):
- The kernel has already been started, but grub_initrd_load() is called from the stub, not the kernel proper
- The target buffer is owned by the stub and is not accessible to the kernel until the stub returns
- So even on this path, there is no window where unverified data could be used

The verification happens immediately after the read, in the same function, with no intervening calls that
could introduce a race.

== 4. Deferred verifiers are measurement-only ==

Verified that only measurement verifiers (not authentication) are deferred:

TPM verifier (commands/tpm.c):
- Marked with in_place = true (would be added in this MR)
- init() function returns GRUB_VERIFY_FLAGS_SKIP_VERIFICATION when not in enforce mode (line ~123-126 in
  existing code)
- When in enforce mode, init() returns GRUB_VERIFY_FLAGS_DEFER_AUTH (line ~131)
- write() function extends PCR (measurement only, does not authenticate)
- Result: measurement happens in grub_verify_in_place(), but authentication (if enabled) happens at open
  time via the DEFER_AUTH mechanism

TPCM verifier (commands/tpcm.c):
- Marked with in_place = true (would be added in this MR)
- Similar structure to TPM verifier
- Measures to event log but does not authenticate

Checked the in_place handling in verifiers.c:
- Line 143-147: If both in_place flag and ver->in_place are true, skip init/write at open time, set
  verify_pending, continue to next verifier
- Line 164-170: If no verifier ran (all were deferred), check for DEFER_AUTH request - if present, fail with
  "One or more verifiers require deferred authentication" (line 169)
- This means: if a verifier sets DEFER_AUTH, it MUST run at open time (not be deferred), ensuring
  authentication happens before the file can be used

grub_verify_in_place() handling (verifiers.c:349-351):
- When a verifier returns DEFER_AUTH or SKIP_VERIFICATION, close the context and continue (lines 349-352)
- Comment at line 344: "A DEFER_AUTH request is answered in grub_verifiers_open(), which is the only place
  seeing every verifier. Measuring the file here does not authenticate it, so there is nothing to do about
  it here."
- This confirms that authentication is not deferred - it happens at open time

Conclusion: The design correctly separates measurement (can be deferred) from authentication (must happen at
open time). A verifier cannot both defer and authenticate; if it requests DEFER_AUTH, it will run at open
time and block the file from being used if authentication fails.

== 5. Additional safety checks ==

File type mismatch check (verifiers.c:313-315):
grub_verify_in_place() verifies the file was opened with VERIFY_IN_PLACE flag:

  if ((io->type & GRUB_FILE_TYPE_VERIFY_IN_PLACE) == 0)
    return grub_error (GRUB_ERR_BAD_ARGUMENT, N_("in-place verification not requested: %s"), io->name);

This prevents callers from accidentally calling grub_verify_in_place() on files that were not opened with
the flag (which would skip important setup done at open time).

Double-call detection (verifiers.c:323-325):
If verify_pending is not set, grub_verify_in_place() logs a debug message:

  if (!io->verify_pending)
    grub_dprintf ("verify", "file %s: grub_verify_in_place() called without a prior VERIFY_IN_PLACE open,
                  or called twice\n", io->name);

This helps catch bugs where the function is called multiple times (the flag is cleared at line 326, so a
second call would see verify_pending = 0).

Exemption consistency (verifiers.c:84-101, 320):
The grub_verifiers_exempt() helper is shared by both grub_verifiers_open() and grub_verify_in_place(),
ensuring both entry points agree on which files skip verification entirely (signature files, memdisk,
procfs).

== Summary ==

The in-place verification implementation shows good security design:
- Strong coupling enforcement (VERIFY_IN_PLACE requires NO_DECOMPRESS, checked early, no bypass)
- Unverified data cannot reach the kernel (comprehensive buffer wipe on all error paths)
- No TOCTOU (load and verify are adjacent with no intervening access)
- Authentication is never deferred (only measurement verifiers have in_place=true)
- Defense in depth (file type checks, double-call detection, shared exemption logic)

The AI-assisted code is thorough and correct. No security issues found.
