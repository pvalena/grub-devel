## Additional findings

- **bootp.c**: `boot_file_len`/`server_name_len` are zero-initialized instead of left uninitialized.
  Read the full function (`grub_net_configure_by_dhcp_ack`) and confirmed both length variables are
  only ever read inside `if (boot_file)` / `if (server_name)` blocks, and those pointers are always set
  in the same branch as their matching length (never independently). The zero-initialization cannot
  collide with a legitimate value on any reachable path -- straightforward warning fix.
- **ofpath.c**: both `fscanf` calls are cast to `(void)`. In `of_find_fc_host`, `buf[0] = '\0'` already
  runs immediately before the call, so a failed/short scan leaves `buf` as an intentional empty string
  (per the existing comment). In `of_path_get_nvme_nsid`, `nsid` is declared `= 0`, matching the value
  every other early-return path in the function already uses for "not found". Ignoring the result
  changes nothing observable.
- **platform.c**: `strncpy` -> `memcpy` in `add_multiple_nvme_bootdevices`. Since `n == strlen(src)` at
  both call sites, `strncpy` and `memcpy` copy identical bytes here (no truncation, no NUL-padding
  difference); the swap only removes the truncation warning. The pre-existing bounds check
  (`strlen(multipath_boot) + strlen(path) > BOOTDEV_BUFFER`) and its uninitialized-buffer `strlen()`
  read on the first loop iteration are unchanged from `origin/master` and out of scope for this MR.

Commit messages accurately describe the changes; each includes the original compiler warning text,
which matches the code being modified.
