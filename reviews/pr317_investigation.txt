Category 1: Memory Leak Fixes
------------------------------

VERIFIED: grub-core/io/gzio.c - huft_build leak
- Original: `if (h) huft_free (u[0]); return 3;`
- Bug: When h==0 but tree already allocated (*t = q + 1), leak occurs
- Fix: Remove `if (h)` (huft_free handles NULL) + null caller's pointer
- Cross-check: huft_free implementation confirms NULL-safe loop
- Result: CORRECT FIX

VERIFIED: grub-core/io/lzopio.c - uncompress_block leak
- Original: Multiple `return -1` after allocating udata/cdata
- Bug: Error returns don't free allocated buffers
- Fix: Adds fail label with cleanup + NULL assignment
- Key insight from comment: "buffer left behind would be handed to next read without validation"
- Also adds usize check after decompression (missing validation)
- Result: CORRECT FIX

VERIFIED: grub-core/loader/linux.c - grub_initrd_init leaks
- Pattern: components[i].newc_name allocated but nfiles not yet incremented
- Bug: Error paths call grub_initrd_close which uses nfiles as cleanup bound
- Affects three paths: insert_dir failure, overflow, file-open failure
- Fix: Explicit grub_free(newc_name) + free_dir(root) before grub_initrd_close
- Cross-check: Confirmed nfiles++ only after successful file open
- Result: CORRECT FIX

VERIFIED: grub-core/lib/xzembed/xz_dec_stream.c - decoder reuse leak
- Context: SquashFS decompresses each block via xz_dec_reset + xz_dec_run
- Bug: dec_stream_header re-runs on each reuse, reallocates contexts without freeing old
- Fix: Pre-free crc32_context + 3 hash contexts before reallocation, null s->hash
- Includes fail_hash cleanup with careful NULL-after-free (contexts freed by xz_dec_end too)
- Cross-check: Verified xz_dec_reset keeps pointers but dec_stream_header overwrites them
- Result: CORRECT FIX

VERIFIED: grub-core/commands/loadenv.c - check_blocklists leak
- Original: Two early returns after grub_malloc(blockbuf)
- Bug: No grub_free on error paths
- Fix: Add grub_free(blockbuf) before both returns
- Also adds final grub_free(blockbuf) on success path
- Result: CORRECT FIX

VERIFIED: grub-core/io/gzio.c - one-shot decompressor leak
- Functions: grub_zlib_decompress / grub_deflate_decompress
- Bug: Call grub_gzio_read_real but not grub_gzio_close, leaving tl/td/hcontext allocated
- Fix: Add explicit cleanup matching grub_gzio_close (huft_free tl/td, grub_free hcontext)
- Cross-check: Confirmed grub_gzio_close does this cleanup
- Result: CORRECT FIX

VERIFIED: grub-core/io/{gzio,lzopio,xzio,zstdio}.c - filename leak
- Pattern: All set `file->name = 0` in close functions
- Bug: Filters get their own filename copy (grub_file_open gives each filter its own)
- Original comment: "Device and name are freed by parent" - WRONG
- Fix: Remove `file->name = 0` line (grub_file_close will free it)
- Updated comment in kern/verifiers.c explains: "grub_file_open() gives each filter its own copy"
- Result: CORRECT FIX

VERIFIED: grub-core/script/script.c - parser error path leak
- Complex: bison discards $<memory>$ values on error without calling record_stop
- Bug: Outer-scope mem chains become unreachable via state->memused
- Fix: Introduces grub_script_mem_save stack to track saved chains + saved_scripts
  - grub_script_mem_record: pushes save (with saved mem + saved_scripts) onto stack
  - grub_script_mem_record_stop: pops from stack on success
  - Error path: drains mem_saves stack, freeing orphaned chains + scripts
- Also frees parsestate->scripts (completed block arguments, separate malloc)
- Result: CORRECT FIX (sophisticated tracking for parser error recovery)

Category 2: Undefined Behavior Fixes
-------------------------------------

VERIFIED: include/grub/misc.h - grub_strtol LONG_MIN negation
- Case: magnitude = GRUB_LONG_MAX + 1 (i.e., unsigned representation of |LONG_MIN|)
- Original: `return -((long) magnitude);`
- Bug: Casts to LONG_MIN, then negates it - signed overflow, undefined behavior
- Fix: `return (long) (-magnitude);` - negate in unsigned domain first
- Result: CORRECT FIX

VERIFIED: grub-core/lib/adler32.c - shift overflow
- Original: `ctx->a | (ctx->b << 16)`
- Bug: ctx->a and ctx->b likely uint16_t, promote to signed int; shift 16 bits can overflow
- Fix: Cast both to grub_uint32_t before operations
- Result: CORRECT FIX

VERIFIED: grub-core/lib/zstd/zstd_decompress.c - pointer arithmetic overflow
- Original: `seq.match = matchBase + pos - seq.offset;`
- Original comment admits: "can overflow when seq.offset is really too large"
- Bug: Pointer arithmetic outside object bounds when offset large (corrupted input) - UB
- Fix: `(const BYTE*)((uintptr_t)matchBase + (uintptr_t)pos - (uintptr_t)seq.offset)`
- Does arithmetic in integer domain (well-defined wrap), then casts to pointer
- Result: CORRECT FIX

VERIFIED: grub-core/script/execute.c - NULL pointer arithmetic
- Original: `scope->argv.args -= scope->shifts;`
- Bug: When function called with no args, args is NULL and "NULL -= 0" is undefined
- Fix: Guard with `if (scope->shifts)` - only applies when there were args to shift
- Comment explains: "shift can only have happened when there were arguments, so args is non-NULL
  whenever shifts != 0"
- Result: CORRECT FIX

VERIFIED: include/grub/list.h - GRUB_FIELD_MATCH UBSan
- Original: `&(ptr)->field` when ptr NULL
- Bug: Address-of-member on null pointer triggers UBSan (UB even though compile-time constant)
- Fix: Use __builtin_offsetof instead - same result (offset comparison) without pointer ops
- Result: CORRECT FIX

Category 3: DoS Prevention
---------------------------

VERIFIED: grub-core/gettext/gettext.c - number_of_strings DoS
- Original: `ctx->grub_gettext_max = grub_le_to_cpu32 (head.number_of_strings);`
  followed by `grub_calloc (ctx->grub_gettext_max, ...)`
- Bug: Untrusted count from .mo header used directly for allocation + loop bound
- Attack: Huge count (millions) makes calloc succeed (lazy pages) but costs seconds in
  grub_gettext_delete_list loop - amplification from 20-byte header
- Fix: Cap at GRUB_GETTEXT_MAX_STRINGS (65536) - GRUB's own catalog has <2000
- Cross-check: Verified grub_gettext_delete_list loops to grub_gettext_max
- Result: CORRECT FIX

VERIFIED: grub-core/gettext/gettext.c - string length DoS
- Bug: String descriptor length from .mo used directly as grub_malloc size
- Attack: Multi-gigabyte allocation from tiny crafted file
- Fix: Cap at GRUB_GETTEXT_MAX_STRING_LEN (65536) in grub_gettext_getstr_from_position
- Check happens before grub_add(length, 1, &alloc_sz)
- Result: CORRECT FIX

VERIFIED: grub-core/commands/loadenv.c - environment block size DoS
- Bug: grub_file_size(file) used directly for grub_malloc without upper bound
- Fix: Adds GRUB_ENVBLK_MAXSIZE (8MB) cap before allocation
- Real blocks are ~1KB; 8MB is generous headroom
- Also has existing lower bound check (< sizeof signature) after read
- Result: CORRECT FIX
