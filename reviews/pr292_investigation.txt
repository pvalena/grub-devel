== Verification of fix 1: Trailing whitespace tolerance ==

Read `.gitlab-ci/script/metadata-sob.sh` at pr292 (04da713a0), lines 15-18:

```sh
SOB_FORMAT="Signed-off-by: NAME LASTNAME <USER@DOMAIN.TOPLEVELDOMAIN>"
SOB_REGEX='^Signed-off-by:[[:space:]]+[^<>[:space:]].*<[^[:space:]<>@]+@[^[:space:]<>@]+\.[^[:space:]<>@]+>\s*$'

echo "Checking commits for Signed-off-by label..."
```

The regex now ends with `>\s*$` instead of `>$`. `\s*` matches zero or more whitespace characters
(space, tab, `\r`, vertical tab, form feed) before the end-of-line anchor. This allows:

- `Signed-off-by: John Doe <jdoe@example.com>` (no trailing whitespace) — matched
- `Signed-off-by: John Doe <jdoe@example.com> ` (trailing space) — matched
- `Signed-off-by: John Doe <jdoe@example.com>\r` (trailing `\r`) — matched

The prior version's `>$` anchor required the closing `>` to be immediately followed by EOL,
rejecting any trailing whitespace. This was a robustness gap because:

1. `git commit` and `git am` strip trailing per-line whitespace by default (cleanup is standard).
2. `git commit-tree` (the plumbing command used by GitLab/GitHub web UIs, libgit2-based tooling,
   and API-driven squash/rebase flows) stores the message byte-for-byte with no cleanup. Trailing
   whitespace from a GUI text box or a mailing-list patch passed through various clients is
   preserved.

The GRUB corpus receives patches from mailing lists (kernel.org/grub-devel), making the
commit-tree path plausible. A well-formed trailer that happens to carry a trailing space or `\r`
(e.g., Windows line ending from a cross-platform mail client) now passes the format check instead
of failing with a misleading "Wrong Signed-off-by format" error.

The check still fails closed: it rejects valid input (false negative) at worst, never accepts
invalid input (no false positive), so the prior version's gap was not exploitable — the fix purely
eliminates false rejections.
