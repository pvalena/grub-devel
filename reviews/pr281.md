# AI Review: MR !281 - disk/i386/pc/biosdisk: Fix retry of CDROM reads

1 commit fixes the INT13 extensions CD-ROM read retry loop so a retry cannot silently return no
data.

**Commits:**
1. **a729f6907** - disk/i386/pc/biosdisk: Fix retry of CDROM reads

## Issues Found

No issues found.

## Additional findings

`dap->blocks` is set once to `size` before the retry loop. `grub_biosdisk_rw_int13_extensions()`
passes the same `dap` pointer to the real-mode INT13 AH=42h BIOS call on every iteration; per the
bug report this MR fixes, some BIOSes overwrite the disk-address-packet's block count field
in place (e.g. with the number of blocks actually transferred) even on a failed call, so a
naive retry reads with `dap->blocks == 0` and reports success while filling nothing. Resetting
`dap->blocks = size` after each failed attempt, before the next iteration, is a self-contained fix
that only affects the CD-ROM/LBA extensions path (`GRUB_BIOSDISK_FLAG_CDROM` && `GRUB_BIOSDISK_FLAG_LBA`);
it is a no-op on BIOSes that do not mutate the packet, since `size` is unchanged between attempts.
The `i == GRUB_BIOSDISK_CDROM_RETRY_COUNT` failure check after the loop is untouched and still
correct.
