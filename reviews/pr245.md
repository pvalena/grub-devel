# AI Review: MR !245 - Allow "fallback" to include entries by title, not just number

1 commit: `get_and_remove_first_entry_number()` now matches a non-numeric `fallback` value against menu entry titles
and ids, reusing `menuentry_eq()` (moved up in the file and changed to return the matched length).

**Commits:**
1. **970837638** - Allow "fallback" to include entries by title, not just number.

## Issues Found

### Issue 1: After a title/id match, `tail += sz` advances from the wrong base and by the wrong length

**Location:** `grub-core/normal/menu.c`, `get_and_remove_first_entry_number()`, line 240, and `menuentry_eq()`,
line 184

The code assumes `tail == val` and that `sz` counts characters of `val`. Neither holds in two cases:

- On a failed parse `grub_strtoul()` leaves `*end` *after* any leading whitespace (and after a `0x` prefix)
  (`kern/misc.c:597, 609, 656`), while `menuentry_eq()` compares from `val[0]`. With `menuentry " A" { ... }` and
  `fallback=" A"` the title matches (`sz = 2`), but `tail = val + 1`, so `tail + sz` is `val + 3`, one byte past the
  NUL of the 2-character value. The `grub_isspace` loop and `grub_env_set (name, tail)` then read stale heap bytes
  and `fallback` is set to garbage (which can even parse as an entry number on the next pass).
- The full-match return is `ptr1 - id` (id characters), unlike the `>` return which is `ptr2 - spec` (spec
  characters). For a title containing `>` written escaped in the spec (`A>B` matched by `A>>B`) it is one short,
  leaving `B` behind as a bogus second fallback entry.

Both need an unusual title (leading whitespace, a `0x` start, or a `>`), so ordinary configs are not affected.

**Draft fix** -- compute the advance from `val` and count spec characters in every return:

```diff
--- a/grub-core/normal/menu.c
+++ b/grub-core/normal/menu.c
@@ -181,7 +181,7 @@ menuentry_eq (const char *id, const char *spec)
       if (*ptr1 != *ptr2)
 	return 0;
       if (*ptr1 == 0)
-	return ptr1 - id;
+	return ptr2 - spec;
       ptr1++;
       ptr2++;
     }
@@ -237,7 +237,7 @@ get_and_remove_first_entry_number (grub_menu_t menu, const char *name)
   if (grub_errno == GRUB_ERR_NONE)
     {
       if (sz > 0)
-	tail += sz;
+	tail = val + sz;
 
       /* Skip whitespace to find the next entry.  */
       while (*tail && grub_isspace (*tail))
```

## Additional findings

A title or id only matches when it is the whole remaining value or is followed by `>`, so a space-separated list of
titles/ids (`fallback="idA idB"`) is still dropped as before; only numbers can be listed. The remainder after `>` is
left in `fallback` and discarded on the next pass, as already happens for `1>0` before this patch.
