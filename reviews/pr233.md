# AI Review: MR !233 - ieee1275/ofdisk: fix NULL deref and UAF in ofdisk_hash_add

1 commit hardening `ofdisk_hash_add()`: it fixes a use-after-free on `curcan`, a NULL
dereference on `pcan`, and adds a NULL guard to `check_string_removable()`.

**Commits:**
1. **0535bee6d** - ieee1275: ofdisk: fix NULL deref and use-after-free in ofdisk_hash_add

The two fixes the commit targets are real and correctly handled:

- **UAF on `curcan`**: the `else` branch now sets `curcan = NULL` after `grub_free (curcan)`,
  and `check_string_removable()` short-circuits on NULL, so the later
  `check_string_removable (curcan)` no longer reads freed memory.
- **NULL deref on `pcan`**: the `if (!pcan)` check is moved *before* the
  `pcan->is_removable = 1` / `pcan->shortest` dereferences, so a failed
  `ofdisk_hash_add_real (curcan)` returns early instead of crashing.

## Issues Found

### Issue 1: `curcan` leaked on the new `ofdisk_hash_add_real (curcan)` failure path

**Location:** `grub-core/disk/ieee1275/ofdisk.c`, `ofdisk_hash_add()`, lines ~195-199

The new early return added to fix the NULL deref leaks `curcan`:

```c
  if (!pcan)
    pcan = ofdisk_hash_add_real (curcan);   /* on failure, curcan is not stored */
  else
    {
      grub_free (curcan);
      curcan = NULL;
    }

  if (!pcan)
    {
      grub_errno = GRUB_ERR_NONE;
      return p;                             /* curcan still owned here, never freed */
    }
```

`ofdisk_hash_add()` owns `curcan`: the caller `dev_iterate_real()` does
`can = grub_strdup (path)` and passes it in without freeing it afterwards. The function
otherwise honours that contract — it frees `curcan` when `pcan` already exists, and stores
it (`p->devpath = devpath`) when `ofdisk_hash_add_real()` succeeds. But on the failure path,
`ofdisk_hash_add_real (curcan)` frees only its own `p` on error, not the passed string, so
`curcan` is orphaned and the new `return p` leaks it. This path only triggers on allocation
failure (OOM), so impact is low, but it is a leak newly introduced by this patch in a
function whose purpose is fixing memory-safety bugs.

**Draft fix** -- free `curcan` before returning:

```diff
--- a/grub-core/disk/ieee1275/ofdisk.c
+++ b/grub-core/disk/ieee1275/ofdisk.c
@@ -193,6 +193,7 @@ ofdisk_hash_add (char *devpath, char *curcan)
 
   if (!pcan)
     {
+      grub_free (curcan);
       grub_errno = GRUB_ERR_NONE;
       return p;
     }
```

## Additional note

Pre-existing, not introduced by this MR: `p = ofdisk_hash_add_real (devpath)` (line ~173) is
also not NULL-checked before `p->shortest = p->devpath` in the `if (!curcan)` branch (line
~181) and before the `pcan->shortest`/`p->devpath` uses below. `ofdisk_hash_add_real()` can
return NULL on OOM/overflow. Since this MR is specifically about NULL-hardening this
function, guarding `p` too would round it out, but it is outside the current diff.
