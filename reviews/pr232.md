## Issues Found

### Issue 1: `grub_get_datetime()` return value ignored; `current_dt` used uninitialized

**Location:** `grub-core/commands/appendedsig/x509.c`, `x509_check_validity()`, lines ~1014-1044

`current_dt` is an uninitialized local. `grub_get_datetime()` returns `grub_err_t`, but its
result is discarded:

```c
  struct grub_datetime current_dt;
  ...
  grub_get_datetime (&current_dt);          /* return value ignored */
  ...
  if (!grub_datetime2unixtime (&current_dt, &current_epoch))   /* uses possibly-garbage dt */
```

On `powerpc_ieee1275` (one of only two platforms that build `appendedsig`; the other is
`emu`), `grub_get_datetime()` returns `GRUB_ERR_IO` **without writing to `*datetime`** when
the RTC node can't be opened or the OF `get-time` call fails
(`grub-core/lib/ieee1275/datetime.c`: "couldn't open RTC" / "get-time failed" both `return`
before assigning any field). In that case `current_dt` holds stack garbage.

Consequence: on a system with no working RTC, validity enforcement operates on undefined
data. `grub_datetime2unixtime()` either rejects the garbage (→ `GRUB_ERR_BAD_NUMBER`,
returned as the validity result) so that a legitimately-signed kernel fails verification and
the machine will not boot, or — if the garbage happens to land in range — it silently
compares the certificate against a bogus "current time", non-deterministically accepting an
expired certificate or rejecting a valid one depending on stack contents. This is exactly
the case the deleted comment warned about ("we have no true time source on several
platforms").

**Draft fix** -- check the return value and fail closed (a validity check that cannot read
the clock should not pass):

```diff
--- a/grub-core/commands/appendedsig/x509.c
+++ b/grub-core/commands/appendedsig/x509.c
@@ -1019,7 +1019,11 @@ x509_check_validity (const grub_x509_cert_t *cert)
   if (cert == NULL)
     return grub_error (GRUB_ERR_BAD_ARGUMENT, "bad input certificate");
 
-  grub_get_datetime (&current_dt);
+  if (grub_get_datetime (&current_dt) != GRUB_ERR_NONE)
+    {
+      grub_dprintf ("appendedsig", "failed to read the system clock\n");
+      return GRUB_ERR_IO;
+    }
```

The draft stops the uninitialized read, which is unambiguous. The failure *policy* is a
design decision the author should confirm: failing closed makes an RTC-less powerpc system
unable to verify any appended signature (previously validity was intentionally not checked
at all). If the intent is to skip validity when no clock is available rather than reject,
that is a different fix and needs to be stated explicitly.
