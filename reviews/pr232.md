# AI Review: MR !232 - appendedsig X.509 certificate validity checking (re-review)

3 commits adding X.509 `notBefore`/`notAfter` parsing and enforcing certificate validity
when certificates are loaded into the trust store and when signatures are verified.

**Commits:**
1. **9cd559739** - appendedsig/x509: Parse X.509 certificate validity period
2. **c5b2a76c6** - appendedsig/x509: Implement X.509 certificate validity check helper
3. **715eca44b** - appendedsig/pkcs7: Enforce X.509 validity period checks on certificate
   load and verification

## Re-review

The previously reviewed revision (tips `b6b0723ca`/`443fadb78`/`3627367bc`) had one issue:
`x509_check_validity()` ignored the return of `grub_get_datetime()` and then read the
uninitialized `current_dt`, which on `powerpc_ieee1275` (RTC failure leaves `*datetime`
unwritten) produced UB and a nondeterministic accept/reject of a signed kernel.

**That issue is fixed.** The current revision applies exactly the guard suggested:

```c
  if (grub_get_datetime (&current_dt) != GRUB_ERR_NONE)
    {
      grub_dprintf ("appendedsig", "failed to read the system clock\n");
      return GRUB_ERR_IO;
    }
```

The rework was broader than the fix, so all three commits were re-reviewed in full. Two
latent problems in the earlier revision were also corrected along the way (see Additional
findings). The failure *policy* remains fail-closed (no readable clock ⇒ no cert verifies on
an RTC-less powerpc box); that is the author's stated design choice, now applied consistently
at both enforcement sites.

## Issues Found

No issues found.

## Additional findings

- **UTCTime year fixed:** the earlier revision mapped 2-digit years `>= 50` with
  `1950 + year` (so `"50"` became 2000); it is now `1900 + year`, matching RFC 5280
  (`YY >= 50` ⇒ `19YY`). The `< 50 ⇒ 20YY` half was already correct.
- **Day validation tightened:** the flat `day > 31` bound was replaced by
  `x509_days_in_month(year, month)`, which is leap-year aware. `month` is range-checked
  (`< 1 || > 12`) with `||` short-circuit *before* `x509_days_in_month()` is called, so the
  `days[month - 1]` lookup can never go out of bounds.
- **Time-buffer bounds are safe:** `x509_get_time()` is called with `raw_time_len - 1`.
  `grub_asn1_allocate_and_read()` returns a buffer of `data_size + 1` bytes (libtasn1's
  `PUT_AS_STR_VALUE` appends a NUL and reports `data_size + 1`), so for the accepted 13-byte
  (UTCTime) and 15-byte (GeneralizedTime) forms the highest index read (the `'Z'` at
  `len - 1`) stays inside the allocation. Non-13/15 lengths are rejected before any digit is
  read.
- **Enforcement wiring is correct:** `check_validity` is added to `grub_x509_spec_t` in the
  same slot in the typedef and the sole initializer `_grub_x509_spec`, so it is never NULL at
  the two call sites (`add_certificate()`, `pkcs7_get_signer_cert()`). `x509_get_validity()`
  frees `type`, `validity_path`, and `raw_time` on every path (no leak).
