--- Commit 4 (8a915a5f8): posix_wrap/assert.h uses libc assert in utility builds ---
Read the file at both refs. New shape: `#if defined (GRUB_UTIL) || !defined (GRUB_MACHINE)` -> `#include_next
<assert.h>` (outside any guard); `#else` -> the original guarded body; two `#endif`s balanced.
- The condition is the same as config.h.in:71, the branch that includes config-util.h, so exactly the translation
  units that receive gnulib's `static_assert` shim get libc assert.h. The pinned gnulib's m4/assert_h.m4
  (AH_VERBATIM zzstatic_assert) confirms the shim: when the compiler's static_assert is not a keyword (as with
  -std=gnu99) and `assert` is not already defined, it appends `#include <assert.h>` followed by `#undef assert`.
  That is why the include_next branch is deliberately outside the include guard (a later `#include <assert.h>` has
  to define assert again); libc's assert.h is designed to be re-included.
- Where posix_wrap meets that branch: libgrubgcry.a (util/import_gcry.py:104-107: cflags $(CFLAGS_GCRY), cppflags
  $(CPPFLAGS_GCRY); conf/Makefile.common:84-87 puts $(CPPFLAGS_POSIX) in CPPFLAGS_GCRY). It is a host library built
  with HOST_CPPFLAGS, which carry -DGRUB_UTIL=1 (configure.ac:132). Before the change the shim's `#include <assert.h>`
  resolved to posix_wrap/assert.h, whose `#include <grub/misc.h>` runs while grub/symbol.h (which includes config.h at
  line 22) is still mid-inclusion, as the commit message says. Target and emu modules (no GRUB_UTIL in grub-core's
  compile flags, as far as grep of Makefile.core.def/Makefile.am/gentpl.py/conf/Makefile.common shows) take the
  unchanged #else branch.
- Runtime effect: under the new branch `assert` is libc's (abort on failure) rather than assert_real (prints and
  continues). I looked for live `assert()` calls in what libgrubgcry builds: libgcrypt's only live calls are
  cipher/scrypt.c:81 (excluded by util/import_gcry.py:147-148, "TODO: Support scrypt KDF") and src/hmac256.c:664
  (src/ contributes only const-time.c, import_gcry.py:111-112); libgcrypt-grub/ and libgcrypt_wrap/ have none. zstd's
  assert is compiled out at the default DEBUGLEVEL 0 (debug.h:65-70 defines `assert(c) ((void)0)` unless assert is
  already defined; zstd_deps.h:90-97 only includes <assert.h> under ZSTD_DEPS_NEED_ASSERT, set when DEBUGLEVEL >= 1).
  So this is a runtime no-op for current callers, as the commit says. (grub-core/lib/reed_solomon.c calls assert
  live, but it is not built with the posix_wrap include path; see observation A.)
