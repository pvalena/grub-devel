# AI Review: MR !283 - ZFS: support replacing/spare vdevs and walk the full leaf-device tree

2 commits fix GRUB's handling of ZFS pools with an active "zpool replace" or hot spare: the
in-tree ZFS driver rejected the transient "replacing"/"spare" vdev types outright, and the host
`grub-probe`/`grub-install` device-discovery code only ever descended through the first child at
each level, so it missed sibling leaves and aborted instead of degrading gracefully.

**Commits:**
1. **db1932c1f** - fs/zfs/zfs: Support replacing and spare vdevs
2. **1308c4727** - osdep/unix/getroot: Walk the whole ZFS vdev tree

## Issues Found

No issues found.

## Additional findings

`fill_vdev_info_real()` now routes `VDEV_TYPE_REPLACING`/`VDEV_TYPE_SPARE` into the same branch
as `VDEV_TYPE_MIRROR` (both types are pre-existing defines in `include/grub/zfs/zfs.h`), setting
`fill->type = DEVICE_MIRROR`. `read_device()`'s `DEVICE_MIRROR` case already tries every child in
order and returns on the first successful read, which is the correct semantics for a
replacing/spare vdev (read from whichever of the old/new/spare device works) and requires no
changes elsewhere.

`add_zfs_leaf_devices()` (new in `getroot.c`) replaces the old single-descent loop with proper
recursion: it walks every "children" array all the way down and only collects nodes that
resolve to a "path" (skipping holes/missing/indirect vdevs), matching the commit's stated fix for
siblings of a "replacing" node being silently dropped. It also guards `zpool_open()` failure
(the old code dereferenced the handle unconditionally) and drops the misleading `error(1, ...)`
aborts in favor of skipping unreadable leaves, so a pool with a transient vdev degrades to
"leaf devices found" instead of exiting the whole tool. The realloc/append pattern and the
Solaris `/dev/dsk` -> `/dev/rdsk` rewriting are carried over unchanged from the original code.
