# AI Review: MR !267 - ieee1275: ofdisk: enumerate all PCIe NVMe namespaces

1 commit adds PCIe NVMe namespace discovery to the IEEE1275 disk backend: a new
`dev_iterate_pcie_nvme()` calls the OF "get-namespace-list" client-interface method on an NVMe
controller node (identified by device_type "nvme" or POWER's "nvm-e") and registers one disk per
namespace ID, falling back to walking the controller's real OF child nodes when the method is
unavailable. A companion guard skips generically-walked "namespace" block nodes so they are not
registered a second time.

**Commits:**
1. **a464afd71** - ieee1275: ofdisk: enumerate all PCIe NVMe namespaces

No issues found.

## Additional findings

Resource handling (the constructed path buffer and the controller ihandle) is balanced on all
five return paths of `dev_iterate_pcie_nvme()`, and is more defensive than the pre-existing
`dev_iterate_fcp_nvmeof()` it is modeled after: it copies the firmware-returned NSID table into
a bounds-checked local array before closing the ihandle (the sibling reads its table after
closing), and it checks the IEEE1275 `catch_result` in addition to the entry-function's return
(the sibling checks only the latter). The new "skip node named `namespace`" guard added to the
generic block-device dispatch path is a real fix, not a workaround for a hypothetical: the
pre-existing "fcp" dispatch arm has no early `return` and falls through to the generic recursive
child walk, so without this guard a namespace node also reachable as a real OF child would be
registered twice (once by the explicit enumeration, once by the generic walk) — this now applies
correctly to both the new PCIe path and the existing FC-NVMeoF path.
