## Additional findings

The HBA-addressing lookup is factored out into `hba_addressing()` (same logic as the previous
inline code: `check_hba_identifiers()` plus the `sparc_lsi_hba[]` table lookup, both unchanged)
and is now called unconditionally near the top of `of_path_of_scsi()`, before the `vendor_is_ATA()`
check, instead of only inside the final SAS-address-formatting branch. None of the calls in
between (`check_sas()`, `vendor_is_ATA()`) mutate `sysfs_path`, so moving the computation earlier
does not change its result for any existing (non-ATA) caller - traced each of the three helpers to
confirm they take `const char *` and only read. For non-SPARC builds the new `#ifdef __sparc__`
blocks compile out entirely, leaving the original unconditional ATA early-return, so there is no
behavior change on other platforms.

On SPARC, the new `ata_wwn()` helper only replaces the early ATA return when
`addressing == GRUB_OFPATH_SPARC_WWN_ADDR` *and* it successfully parses a `naa.<hex>` WWN from
the device's `wwid` sysfs file; `ata_wwn()` only writes its `*wwn` out-param on that exact success
path (a failed `sscanf` leaves it untouched), so falling through to the general SAS-formatting
code always has a valid `sas_address` when reached. Every other ATA disk (non-LSI HBA, or an LSI
HBA using target/lun addressing) keeps taking the old `__of_path_common()` fast path unchanged.
`ata_wwn()`'s own buffer handling (`buf[32]`, zeroed before a bounded `read()`, `fd` closed on the
success path and skipped only when `open()` itself failed) has no overflow or leak.
