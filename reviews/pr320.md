# AI Review: MR !320 - Only blit dirty scanlines on buffer swap

1 commit across `efi_gop.c`, `fb/video_fb.c`, and `video_fb.h`. Adds scanline-range dirty
tracking to the generic framebuffer layer (`grub_video_fb_set_dirty_tracking()` /
`grub_video_fb_take_dirty()`) and opts efi_gop's self-managed shadow buffer into it, so
`grub_video_gop_swap_buffers()` only `Blt()`s the rows that actually changed instead of the
whole screen on every swap.

**Commits:**
1. **d3226441f** - efi_gop: Only blit dirty scanlines on buffer swap

## Issues Found

No issues found.

## Additional findings

Traced the dirty-range lifecycle (arm -> accumulate -> take -> reset) through zero-dirty,
full-first-swap, buffer-edge, and overlapping-draw scenarios -- all correct, no stale carry-over.
`dirty_target` resets in lockstep with `render_target`, so it cannot dangle, and efi_gop is the
only caller of the new functions, so no other driver is affected. Noted a pre-existing, unrelated
leak (`framebuffer.offscreen` realloc without free) confirmed identical on `origin/master` --
not introduced by this patch.
