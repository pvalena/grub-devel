## Additional findings

The change is contained and defaults to prior behaviour: `struct grub_gui_list_impl` is
`grub_zalloc`'d (`grub_gui_list_new()`), so `icon_offset` starts at 0, leaving
`text_left_offset` and the icon blit position identical to before unless a theme sets it. The
icon (`max_leftpad + self->icon_offset`) and the text (`text_left_offset = self->icon_offset +
self->icon_width + icon_text_space`, then `sviewport.x = max_leftpad + text_left_offset`) both
shift by the same `icon_offset`, so they stay aligned. The `list_set_property` handler parses
it with `grub_strtol (value, 0, 10)`, matching the sibling `icon_width`/`icon_height` setters.
Like those siblings the value is not range-checked, but it comes from the (trusted) theme
file, so this is consistent with existing behaviour, not a new exposure. The `grub.texi`
entry matches the property name.
