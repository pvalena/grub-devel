# AI Review: MR !292 - CI: Check Signed-off-by format

1 commit tightens the `signed-off-by` CI job (`.gitlab-ci/script/metadata-sob.sh`): beyond the
existing presence check for a `Signed-off-by:` trailer, it now also validates the trailer's
shape against a new `SOB_REGEX` (name token + `<user@domain.tld>`), tidies the echoed messages,
and reindents the script (tabs for the `if`/`elif`/`else` bodies, 4 spaces elsewhere). `set -xeu`
drops the `-x` trace flag, consistent with the more descriptive per-commit echo output replacing
it.

**Commits:**
1. **606cc1d75** - CI: Check Signed-off-by format

## Issues Found

### Issue 1: Trailing whitespace/CR on an otherwise valid Signed-off-by line fails the new check

**Location:** `.gitlab-ci/script/metadata-sob.sh`, lines 12 (`SOB_REGEX`), 24 (`MESSAGE=`), 28
(format check)

`SOB_REGEX` ends in a bare `>$`, requiring the closing `>` of the email to be immediately
followed by end-of-line:

```sh
SOB_REGEX='^Signed-off-by:[[:space:]]+[^<>[:space:]].*<[^[:space:]<>@]+@[^[:space:]<>@]+\.[^[:space:]<>@]+>$'
```

`MESSAGE` (line 24) comes straight from `git log -1 --format=%B "$SHA"`, i.e. whatever bytes are
actually stored in the commit object. `git commit`/`git am` strip trailing per-line whitespace
(including a trailing `\r`) by default, but that cleanup is **not** universal: a commit created
via `git commit-tree` (the plumbing command used under the hood by GitLab's/GitHub's web-based
commit APIs, squash/rebase-via-API flows, and libgit2-based tooling) stores the message
byte-for-byte, trailing whitespace included. A perfectly well-formed trailer that happens to have
a trailing space or `\r` — plausible for this corpus's actual source (mailing-list patches passed
through various mail clients / GUIs before landing as a commit) — now fails the new format check
with a misleading "Wrong Signed-off-by format" even though it passed the presence-only check that
existed before this MR. This is a regression introduced by the new check, not a pre-existing
limitation: the old script had no format check at all.

This is a robustness gap, not a security bypass — the check fails closed (rejects valid input,
never accepts invalid input), so it doesn't undermine the hardening's actual goal.

**Draft fix** — allow trailing whitespace before the end of the line:

```diff
--- a/.gitlab-ci/script/metadata-sob.sh
+++ b/.gitlab-ci/script/metadata-sob.sh
@@ -9,7 +9,7 @@
 #
 SOB_FORMAT="Signed-off-by: NAME LASTNAME <USER@DOMAIN.TOPLEVELDOMAIN>"
-SOB_REGEX='^Signed-off-by:[[:space:]]+[^<>[:space:]].*<[^[:space:]<>@]+@[^[:space:]<>@]+\.[^[:space:]<>@]+>$'
+SOB_REGEX='^Signed-off-by:[[:space:]]+[^<>[:space:]].*<[^[:space:]<>@]+@[^[:space:]<>@]+\.[^[:space:]<>@]+>\s*$'
```
