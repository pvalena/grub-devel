# AI Review: MR !296 - osdep/linux: Fix incorrect path prefix in grub2-mkrelpath for btrfs subvolumes

1 commit replacing `get_btrfs_fs_prefix (entries[i].enc_path)` with `xstrdup ("/")` in
`grub_find_root_devices_from_mountinfo()`, so `grub-mkrelpath` no longer prepends the btrfs subvolume path.

**Commits:**
1. **aa28707dc** - osdep/linux: Fix incorrect path prefix in grub2-mkrelpath for btrfs subvolumes

## Issues Found

### Issue 1: `grub-mkrelpath` no longer reports the btrfs subvolume that in-tree consumers depend on

**Location:** `grub-core/osdep/linux/getroot.c`, `grub_find_root_devices_from_mountinfo()`, line ~523

The btrfs branch now always sets `fs_prefix` to `"/"`. For any path on a btrfs subvolume other than the
top-level one (ID 5), or on a bind mount of a subdirectory, `grub_make_system_path_relative_to_its_root_os()`
therefore returns the path relative to the mount point only. Example: with `/` mounted from subvolume `@`,
`grub-mkrelpath /` used to print `/@` and now prints an empty string; `/boot/grub2` used to print
`/@/boot/grub2` and now prints `/boot/grub2`. The commit message says this aligns btrfs with ext4/xfs, but
those take `fs_prefix = entries[i].enc_root` (line 549); the patched btrfs branch ignores `enc_root` as well
(e.g. `mount --bind /top/dir /mnt` gives `/dir/file` before and `/file` after, while ext4/xfs keep `/dir`).

Two consumers in this tree rely on the subvolume being present in that output:

- `util/grub.d/10_linux.in` (lines 70-73) and `20_linux_xen.in` (lines 78-81) build
  `rootflags=subvol=<name>` from `make_system_path_relative_to_its_root /`. With the patch the value is
  empty and the option is never emitted, so the generated kernel command line no longer tells the kernel
  which subvolume to mount as `/`.
- GRUB's btrfs driver resolves absolute paths from the top-level subvolume: `find_path()` starts with
  `get_root()`, which looks up `GRUB_BTRFS_ROOT_VOL_OBJECTID` (5) (`grub-core/fs/btrfs.c` lines 1803-1812,
  1952); the default subvolume is only read by the `btrfs-get-default-subvol` command. Paths that
  grub-mkconfig (`linux`/`initrd` via `rel_dirname`, fonts, themes) and grub-install (`relative_grubdir`,
  `util/grub-install.c:1370`) derive from `grub-mkrelpath` therefore need the `/@` prefix. Without it GRUB
  looks for `/boot/vmlinuz-...` in the top-level subvolume, where it does not exist.

The layout the commit message describes (`/boot` is its own subvolume; the old output it quotes,
`/boot/vmlinuz-...`, implies it sits directly under the top level) is one where the old output is already the
path this tree's GRUB opens; the patched output (`/vmlinuz-...`) is looked up in the top level and not found.
The patch is only right if GRUB's btrfs root is the mounted subvolume, which the btrfs driver in this tree
does not implement.

Not a straightforward fix. The reported use case (`grubby`/`kdumpctl` wanting a path relative to the mounted
subvolume) is a different contract from what the in-tree callers get from `grub-mkrelpath`. Options for the
author: make the new behavior opt-in (new option or environment variable) and keep the default; fix the
consumers that expect the subvolume-relative form; or, if GRUB is meant to treat the mounted subvolume as its
root, change the btrfs driver and the 10_linux/20_linux_xen `rootflags` logic together with this change.

### Issue 2: `get_btrfs_fs_prefix()` becomes an unused static function (`-Wunused-function` with `-Werror`)

**Location:** `grub-core/osdep/linux/getroot.c`, `get_btrfs_fs_prefix()`, lines 265-376

The only call site of `get_btrfs_fs_prefix()` on `origin/master` was the line this patch replaces; on the
branch the definition is the only remaining reference. The function is a file-scope `static` outside any
`#ifdef`, and `getroot.c` is built on Linux through the `#include "linux/getroot.c"` in
`grub-core/osdep/getroot.c` with `HOST_CFLAGS`, which carry `-Wall` and `-Wunused-function`
(`configure.ac:541-544`) plus `-Werror` unless `--disable-werror` is given (`configure.ac:2583-2588`).
Upstream CI configures without `--disable-werror` (`.gitlab-ci/script/build.sh:18-20`), so the expected
result is `'get_btrfs_fs_prefix' defined but not used` as a build error (not compiled here).

**Draft fix** -- only needed if the unconditional `"/"` from Issue 1 is kept: delete `get_btrfs_fs_prefix()`
(lines 265-376). If Issue 1 is resolved by keeping the old behavior as default or behind an option, the
function stays referenced and nothing further is needed.
