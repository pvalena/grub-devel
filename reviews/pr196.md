## Issues Found

### Issue 1: Double-free in `remove_hash_from_db`

**Location:** `appendedsig.c`, `remove_hash_from_db()`, lines ~516-517

The function frees the embedded hash array and then frees the struct itself:

```c
grub_free (curr_hash->hash);
grub_free (curr_hash);
```

`grub_hash_t` defines `hash` as an inline array (`grub_uint8_t hash[GRUB_MAX_HASH_LEN]`), not
a separate allocation. Since `hash` is the first field in the struct, `curr_hash->hash` and
`curr_hash` resolve to the same address. This is a double-free.

Compare with `free_db_list()` which correctly uses `grub_memset` to zero the hash,
then frees only the struct.

**Draft fix** -- replace `grub_free` of the embedded array with `grub_memset`, matching
the pattern in `free_db_list()` and `free_dbx_list()`:

```diff
--- a/grub-core/commands/appendedsig/appendedsig.c
+++ b/grub-core/commands/appendedsig/appendedsig.c
@@ -515,7 +515,7 @@
               grub_dprintf ("appendedsig", "removed distrusted hash %02x%02x%02x%02x.. from the db list\n",
                             curr_hash->hash[0], curr_hash->hash[1], curr_hash->hash[2], curr_hash->hash[3]);
               curr_hash->next = NULL;
-              grub_free (curr_hash->hash);
+              grub_memset (curr_hash->hash, 0x00, sizeof (curr_hash->hash));
               grub_free (curr_hash);
               break;
```

### Issue 2: Memory leak in `x509_get_serial`

**Location:** `x509.c`, `x509_get_serial()`, lines ~380-390

The raw binary serial buffer allocated by `grub_asn1_allocate_and_read` is never freed
after `grub_util_buffer2hex` creates a separate hex string:

```c
serial = grub_asn1_allocate_and_read (...);
if (serial == NULL)
  return grub_errno;

return grub_util_buffer2hex (serial, serial_size, &cert->serial, &cert->serial_len);
// serial never freed
```

Each certificate parse leaks one allocation of the raw serial number.

**Draft fix** -- store the return value, free the raw buffer, then return:

```diff
--- a/grub-core/commands/appendedsig/x509.c
+++ b/grub-core/commands/appendedsig/x509.c
@@ -378,6 +378,7 @@
 x509_get_serial (asn1_node cert_asn1, grub_x509_cert_t *cert)
 {
   grub_int32_t serial_size;
+  grub_err_t ret;
   grub_uint8_t *serial;
 
   serial = grub_asn1_allocate_and_read (cert_asn1, "tbsCertificate.serialNumber",
@@ -385,8 +386,10 @@
   if (serial == NULL)
     return grub_errno;
 
-  return grub_util_buffer2hex (serial, serial_size, &cert->serial,
-                               &cert->serial_len);
+  ret = grub_util_buffer2hex (serial, serial_size, &cert->serial,
+                              &cert->serial_len);
+  grub_free (serial);
+  return ret;
 }
```

### Issue 3: Memory leak in `pkcs7_get_signerinfo_version`

**Location:** `pkcs7.c`, `pkcs7_get_signerinfo_version()`, lines ~155-172

`version_path` is allocated by `grub_xasprintf` but never freed on any return path
(error or success):

```c
version_path = grub_xasprintf ("signerInfos.?%d.version", signer_index + 1);
...
rc = asn1_read_value (pkcs7_asn1, version_path, &version, &version_size);
if (rc != ASN1_SUCCESS)
  return grub_error (...);  // version_path leaked

if (version != 1)
  return grub_error (...);  // version_path leaked

signer->version = 1;
return GRUB_ERR_NONE;        // version_path leaked
```

Leaks one allocation per signer parsed.

**Draft fix** -- free `version_path` after `asn1_read_value`:

```diff
--- a/grub-core/commands/appendedsig/pkcs7.c
+++ b/grub-core/commands/appendedsig/pkcs7.c
@@ -160,8 +160,12 @@
 
   rc = asn1_read_value (pkcs7_asn1, version_path, &version, &version_size);
   if (rc != ASN1_SUCCESS)
-    return grub_error (GRUB_ERR_BAD_SIGNATURE, "error reading signers version: %s",
-                       asn1_strerror (rc));
+    {
+      grub_free (version_path);
+      return grub_error (GRUB_ERR_BAD_SIGNATURE, "error reading signers version: %s",
+                         asn1_strerror (rc));
+    }
+
+  grub_free (version_path);
 
   /* Signature version must be 1 because appended signature only support v1. */
```

### Issue 4: Memory leak in `pkcs7_get_signerinfo_issuer_and_serial`

**Location:** `pkcs7.c`, `pkcs7_get_signerinfo_issuer_and_serial()`, lines ~182-210

`signer_id` is allocated by `grub_asn1_allocate_and_read` but never freed on any
return path:

```c
signer_id = grub_asn1_allocate_and_read (pkcs7_asn1, sid_path, "signer identifier", ...);
grub_free (sid_path);
if (signer_id == NULL)
  return grub_errno;

if (grub_strncmp (signer_id, "issuerAndSerialNumber", signer_id_len) == 0)
  {
    // ... processes issuer and serial ...
    return ret;       // signer_id leaked
  }

return GRUB_ERR_NONE; // signer_id leaked
```

**Draft fix** -- add `grub_free(signer_id)` before each return after its
allocation. Not a straightforward single-line fix because there are multiple
return points inside the `if` block; a `goto cleanup` pattern would be
cleaner but requires restructuring the function.

### Issue 5: Debug message says "failed" on success path

**Location:** `pkcs7.c`, `pkcs7_signed_data_verify()`, lines ~666-674

Both the success (GRUB_ERR_NONE) and failure paths print the same "failed" message:

```c
ret = signer->sig_algo.verify (data, data_len, signer, pk);
if (ret == GRUB_ERR_NONE)
  {
    grub_dprintf ("appendedsig", "verify signer %d ... failed\n", ...);
    return ret;
  }

grub_dprintf ("appendedsig", "verify signer %d ... failed\n", ...);
```

The old code correctly printed "succeeded" on the GRUB_ERR_NONE path.

**Draft fix** -- change the success-path message:

```diff
--- a/grub-core/commands/appendedsig/pkcs7.c
+++ b/grub-core/commands/appendedsig/pkcs7.c
@@ -669,7 +669,7 @@
           grub_dprintf ("appendedsig",
 		        "verify signer %d signatureAlgorithm (%s), issuer ('%s'), and "
 		        "serialNumber (%s) with key PK-Algorithm (%s), issuer ('%s'), "
-		        "and serialNumber (%s) failed\n",
+		        "and serialNumber (%s) succeeded\n",
                         i, signer->sig_algo.name, signer->issuer, signer->serial,
```
