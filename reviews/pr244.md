## Issues Found

### Issue 1: Completion stubs still source the shared `grub` script from `@datarootdir@`, not the new install dir

**Location:** `util/bash-completion.d/*.bash.in` (13 per-tool stubs, line 20 of each, e.g. `grub-install.bash.in`);
`configure.ac`, lines ~350-356

Every stub is only `. @datarootdir@/bash-completion/completions/grub && __grub_<tool>`: it loads the shared `grub`
script by absolute path. The patch changes where `bashcompletion_DATA` (the `grub` script and these stubs) is
installed, but leaves the stubs pointing at `@datarootdir@`. Before the patch both used `$(datarootdir)` and agreed
by construction. Now the install directory is one of two values, and neither is tied to `@datarootdir@`:

- Fallback branch (no `bash-completion.pc`): `${datadir}/bash-completion/completions`. `datadir` and `datarootdir`
  are different variables, so a plain `./configure --datadir=/opt/share` would install into
  `/opt/share/bash-completion/completions` while the stubs source `/usr/local/share/bash-completion/completions/grub`
  (`@datarootdir@` is expanded at `configure.ac:2721`). No bash-completion installation is involved here.
- pkg-config branch: `completionsdir`. The two agree only if it equals `<datarootdir>/bash-completion/completions`.
  With a plain `./configure` (default prefix `/usr/local`, so `@datarootdir@` is `/usr/local/share`) on a host where
  `completionsdir` is, say, `/usr/share/bash-completion/completions`, `make install` would put `grub`, `grub-install`,
  ... there, while `_grub_install` runs `. /usr/local/share/bash-completion/completions/grub`.

In both cases the sourced file does not exist, so the `.` fails, `__grub_<tool>` is skipped and `grub-install <TAB>`
(and the other 12 tools) offers no completion. A `--prefix=/usr` build with the usual layout matches by coincidence,
which hides the problem. (Read from source; configure was not run and no `bash-completion.pc` was inspected.)

**Draft fix** -- have the stubs use the same directory the files are installed to (12 more stubs get the same
one-line change). The `configure.ac` line is needed because the fallback value is the unexpanded `${datadir}/...`
string; the tree already expands `datarootdir` the same way before `AC_OUTPUT`:

```diff
--- a/util/bash-completion.d/grub-install.bash.in
+++ b/util/bash-completion.d/grub-install.bash.in
@@ _grub_install () {
-    . @datarootdir@/bash-completion/completions/grub && __grub_install
+    . @bashcompletiondir@/grub && __grub_install
--- a/configure.ac
+++ b/configure.ac
@@ test "x$exec_prefix" = xNONE && exec_prefix="${prefix}"
 datarootdir="$(eval echo "$datarootdir")"
+bashcompletiondir="$(eval echo "$bashcompletiondir")"
 grub_libdir="$(eval echo "$libdir")"
```
