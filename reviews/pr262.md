## Additional findings

The NVMe-oF rule is unchanged (only a colon after `/namespace@` separates arguments), so devname is identical there;
devargs now uses that colon instead of the last one, returning NULL (not the NQN tail) for a path with no `:partition`.
Behaviour change: for non-NVMe-oF paths `grub_ieee1275_get_devname()` now splits at the last colon, not the first;
devargs has used the last colon since `adeeeeda3`. It differs only if the argument field contains `:`, e.g.
`.../disk@0:3,\:tbxi` (devname gains the args) or an IPv6-style network argument. I found no in-tree producer of such
a path and did not check real firmware bootpaths, so this is an observation.
