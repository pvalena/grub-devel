# AI Review: MR !304 - io/zstdio: Fix heap overrun of the decompression buffers

1 commit fixes a heap buffer underallocation in the zstd decompression I/O wrapper
(`grub-core/io/zstdio.c`): the allocation size calculation used `sizeof(zstdio_t)` (the size of
the pointer type, 4 or 8 bytes) instead of `sizeof(*zstdio)` (the size of the actual structure,
much larger), causing a heap overrun when the structure's fields are accessed. Classic C
sizeof-pointer-vs-sizeof-struct bug.

## Additional findings

The structure `struct zstdio` contains at least seven fixed-size fields (two pointers, two size_t,
two ZSTD buffer structs, one offset) plus a flexible array member (`grub_uint8_t bufs[]`), making
`sizeof(struct zstdio)` substantially larger than `sizeof(struct zstdio *)`. The old allocation
`grub_zalloc(sizeof(zstdio_t) + ZSTD_DStreamInSize() + ZSTD_DStreamOutSize())` allocated only
pointer-size + buffer-sizes bytes, while the structure itself requires its own sizeof + buffer
sizes. Accessing any field beyond the pointer-size allocation (e.g., `zstdio->dctx` at offset 8 on
64-bit) would overrun the heap. The fix changes `sizeof(zstdio_t)` to `sizeof(*zstdio)`, allocating
the full structure size plus the flexible array space.
