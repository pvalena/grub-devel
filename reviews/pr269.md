# AI Review: MR !269 - osdep/linux/ofpath: Update strstr() call in check_hba_identifiers()

1 commit fixing a sparc64-only C23 build failure: under C23 (and glibc-2.43),
`strstr(const char *, const char *)` returns `const char *`, so assigning its result to a
`char *ed` triggers `-Werror=discarded-qualifiers`. A prior commit (675d85810) fixed the
identical pattern in `check_sas()`; this commit applies the same fix to
`check_hba_identifiers()`, which is only compiled under `#ifdef __sparc__` and was missed.

## Additional findings

Beyond the type fix, the commit also drops the `xstrdup()`/in-place-truncate-and-free (`p`)
dance in favor of computing the prefix length (`p_len = ed - sysfs_path`) and printing it
directly from `sysfs_path` with `"%.*svendor"` / `"%.*sdevice"`. This is host-tool code
(`grub-core/osdep/linux/ofpath.c`, built against the system libc), not core GRUB's
`grub_snprintf()`, so -- unlike the unrelated `grub_snprintf()` `"%.*s"` limitation fixed
separately in MR !271 -- glibc's `snprintf()` here fully supports `%.*s`, and the two are not the
same bug or the same function. `path_size` is computed identically to before
(`p_len + sizeof ("vendor")`, matching the old `strlen (p) + sizeof ("vendor")`), and
`sizeof ("vendor") == sizeof ("device")` (both 7 bytes), so reusing `path`/`path_size` for both
the vendor and device reads is unchanged and correctly sized. The removed `free (p)` in the `out:`
label is correct -- `p` no longer exists, and nothing else is leaked in its place.
